# Технический пилот SORT на KITTI 0000

## Условия

Проверено настроечное видео `0000` из KITTI Tracking. На вход базового SORT
подавались прямоугольники Car из GT без идентификаторов. TrackEval получал
полную исходную разметку. Трекер обработал кадры `0–154`. Кадры `0–9` использованы
для прогрева, метрики рассчитаны на кадрах `10–154`.

| Запуск | Условие | Seed | Кадров в маске |
| --- | --- | ---: | ---: |
| `no-loss` | Без искусственных пропусков | — | 0 |
| `burst-l3-s0` | Номинально 50%, серии по три кадра | 0 | 73 |

Бюджет серийной маски составил `floor(0.5 × 145 + 0.5) = 73` кадра
(50,34% участка оценки). Маска содержит 24 серии длиной три кадра и одну
серию длиной один кадр. Любые две соседние серии разделены доступным кадром.
На каждом кадре маски трекер получал пустой массив детекций.

## Метрики

| Условие | NGT | IDF1, % | HOTA, % | DetA, % | AssA, % | FP | FN | IDSW | Frag | RFP на 100 Car |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Без пропусков | 215 | 85,41 | 71,94 | 66,84 | 77,49 | 52 | 16 | 0 | 0 | 24,19 |
| Серии по три кадра | 215 | 50,34 | 41,15 | 43,06 | 39,41 | 83 | 68 | 9 | 9 | 38,60 |

При данной маске IDF1 уменьшился на 35,07 п. п., HOTA — на 30,79 п. п.
Число FP выросло на 31, FN — на 52. RFP вычислен как `100 × FP / NGT`,
где NGT — число экземпляров Car после предобработки KITTI. Результаты
относятся к одному настроечному видео и одной реализации серийной маски.

## Пауза на кадрах 115–117

Выбрана первая трёхкадровая серия, для которой один и тот же подтверждённый
трек получил наблюдение непосредственно перед паузой и на первом
доступном кадре после неё. При наличии нескольких треков выбирался
наименьший ID. Координаты в таблице округлены до сотых пикселя и имеют
порядок `(x1, y1, x2, y2)`.

| Кадр | Детекций на входе | ID трека | `observed` | Выданный бокс |

| 115 | 0 | 1 | `false` | (813.40, 184.16, 925.91, 247.69) |

| Вход | SHA-256 |
| --- | --- |

| `evaluate_tracking.seqmap.training` | `e91464a4e1c14bfe75bb88d51ffe6fe4b7cc65a7433bf15787489b686019710d` |

Из корня проекта задайте пути к входам, подготовьте TrackEval по инструкции
в [README](../../README.md#оценка-sort-в-trackeval) и выполните команды.
Переменная `out` указывает на новый каталог запусков.

```bash
gt=/path/to/label_02/0000.txt
seqmap=/path/to/evaluate_tracking.seqmap.training
out=runs/pilot-0000-gt-sort-new

uv run --locked sort-gap-study run-sort --sequence 0000 --source gt \
  --seqmap "$seqmap" --detections "$gt" --output "$out/no-loss"
uv run --locked sort-gap-study run-sort --sequence 0000 --source gt \
  --seqmap "$seqmap" --detections "$gt" --output "$out/burst-l3-s0" \
  --mask burst --loss-fraction 0.5 --series-length 3 --seed 0

for condition in no-loss burst-l3-s0; do
  uv run --locked sort-gap-study evaluate-sort --run "$out/$condition" \
    --ground-truth "$gt"
done
```

Исходные артефакты сохранены локально в `runs/pilot-0000-gt-sort/`. Каждый
журнал содержит 155 записей по исходным кадрам. Для каждого запуска сверены
номера кадров, ID и координаты в `predictions/data/0000.txt` и `events.jsonl`.
Без пропусков экспортировано 275 оценок, при серийной маске — 270, из них
156 на кадрах маски. В каталоге `repeat/` результаты обоих условий совпали
побайтно с исходными файлами `metrics.csv`, `mask.json`, `events.jsonl`,
`predictions/data/0000.txt`, `protocol.toml` и `manifest.json`.
