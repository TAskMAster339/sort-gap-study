# Влияние серийных пропусков наблюдений на SORT и оценка дополнительной ассоциации

## Запуск SORT на настроечном видео

```bash
uv run --locked sort-gap-study run-sort \
  --seqmap /path/to/evaluate_tracking.seqmap.training --sequence 0000 \
  --source gt --detections /path/to/label_02/0000.txt \
  --mask burst --loss-fraction 0.5 --series-length 3 --seed 0 \
  --output runs/sort-0000-gt-burst
```

Для запуска без искусственных пропусков можно опустить параметры маски.
Для Regionlet укажите `--source regionlet` и файл соответствующего видео из
`det_02`. Для каждого запуска требуется новый каталог `--output`.
Параметр `--method sort-extra` включает второе сопоставление после искусственных
пропусков. По умолчанию используется базовый SORT (`--method sort`).

Для OC-SORT подготовьте локальную копию репозитория.

```bash
git clone --no-checkout https://github.com/noahcao/OC_SORT.git external/OC_SORT
git -C external/OC_SORT checkout --detach 8462e7e729a93ccd3bd995c0a79a890336cb3a0b
```

Добавьте `--method ocsort` к команде `run-sort`. Путь к другой локальной копии
можно передать через `--ocsort-checkout`. Локальная копия в `external/OC_SORT`
также нужна для тестов `tests/test_ocsort.py`.

Чтобы запустить все три метода на одном входе, добавьте `--method all`.
Маска рассчитывается один раз. В новом каталоге запуска появятся подкаталоги
`sort/`, `sort-extra/` и `ocsort/`. Для оценки передайте нужный подкаталог
через `evaluate-sort --run`.

Общий манифест и манифесты методов содержат Git-коммит и признак изменений
рабочей копии на момент запуска, версии среды, пути и SHA-256 конфигурации,
seqmap и входных детекций, а также SHA-256 маски. Маска и конфигурация
сохраняются в корне совместного запуска и в каждом подкаталоге метода.

- `predictions/data/0000.txt` содержит оценки подтверждённых треков в формате
  KITTI Tracking, включая прогнозы на кадрах без наблюдений и оценки на кадрах прогрева.
- `events.jsonl` содержит по одной записи на исходный кадр. `artificial_gap`
  обозначает кадр маски, а `natural_empty` — доступный кадр без детекций после
  фильтрации входа. `matched` и `created` содержат пары
  `[ID трека, индекс поданной детекции]` с нулевой индексацией детекций.
  `removed` содержит ID удалённых треков, а `recovery_candidates` —
  ID треков, допущенных к дополнительной ассоциации на первом доступном кадре
  после паузы, включая случай пустого входа. `recovery_matches` содержит пары
  `[ID трека, индекс поданной детекции]`, найденные на втором этапе.
  В `estimates` поле `observed`
  указывает, была ли использована детекция на текущем кадре.
- `mask.json`, `protocol.toml` и `manifest.json` сохраняют маску, копию
  настроек и сведения о входах и диапазоне кадров.

## Оценка SORT в TrackEval

Один раз подготовьте локальную копию TrackEval. Можно использовать существующий
Git-репозиторий и передать его путь через `--trackeval`.

```bash
git clone --no-checkout https://github.com/JonathonLuiten/TrackEval.git external/TrackEval
git -C external/TrackEval checkout --detach 12c8791b303e0a0b50f753af204249e622d0281a
```

```bash
uv run --locked sort-gap-study evaluate-sort \
  --run runs/sort-0000-gt-burst \
  --ground-truth /path/to/label_02/0000.txt
```

`--ground-truth` указывает на полную разметку KITTI для того же видео при любом
источнике детекций. Команда берёт TrackEval из указанной ревизии Git и сохраняет
`metrics.csv` в каталоге запуска. Участок оценки исключает первые десять
кадров и включает кадры маски. IDF1, HOTA, DetA и AssA записываются в процентах.
Для последовательностей без оцениваемых Car в CSV указывается
`status=no_ground_truth` и оставляется пустое поле RFP.

Локальная копия TrackEval также нужна для запуска тестов `tests/test_evaluation.py`.

## Сводка пилота

```bash
uv run --locked sort-gap-study summarize-pilot \
  --metrics runs/pilot-tune-5.1/metrics.csv \
  --output runs/pilot-summary-5.3
```

Команда сохраняет `by-video.csv` со средними по реализациям маски внутри
каждого видео и `summary.csv` со средними по видео с равными весами.
GT и Regionlet рассчитываются отдельно. Видео с `NGT=0` остаются
в исходной таблице и исключаются из сводки.
`idf1.png` показывает IDF1 в процентах, `fp.png` — среднее число ложных
срабатываний на видео.

### Парный bootstrap для H1

```bash
uv run --locked sort-gap-study analyze-h1 \
  --by-video runs/pilot-summary-5.3/by-video.csv \
  --output runs/pilot-summary-5.3/h1.json --seed 0
```

Для базового SORT при 50% пропусков команда вычитает IDF1 серий длиной
три кадра из IDF1 равномерной маски внутри каждого видео. Для GT и Regionlet
отдельно сохраняются парные разности, средний эффект в процентных пунктах,
95%-й интервал по 5000 выборкам целых видео и одностороннее p до поправки
Holm. Если пары отсутствуют или хотя бы у одного видео отсутствует одна
из двух оценок, указываются статус `unavailable` и `p=1`.

### Дискретная граница и запас RFP для H2

```bash
uv run --locked sort-gap-study analyze-h2 \
  --by-video runs/pilot-summary-5.3/by-video.csv \
  --output runs/pilot-summary-5.3/h2.json --seed 0
```

H2 использует полную сетку серий `1, 2, 3, 5, 8, 10` при 50% пропусков.
Пределы IDF1 и RFP рассчитываются по базовому SORT без пропусков.
Допустимая область заканчивается перед первым нарушением, даже если
последующая длина снова проходит пороги. При прохождении всей сетки
результат содержит нижнюю границу. При нарушении на первой длине
результат содержит статус неопределённой границы.

В каждой из 5000 парных выборок пересчитываются пороги и границы.
Интервал разности длин требует двух конечных границ на исходной выборке
и на всех репликах. Интервал запаса RFP учитывает все границы SORT-extra,
совместимые с одновременной полосой по запасам IDF1 и RFP. Неполная сетка
получает статус `incomplete_grid`. [Правила анализа](docs/hypotheses.md)

### Поправка Holm

```bash
uv run --locked sort-gap-study adjust-holm \
  --h1 runs/pilot-summary-5.3/h1.json --h2 runs/pilot-summary-5.3/h2.json \
  --output runs/pilot-summary-5.3/holm.json
```

Команда сохраняет исходные и скорректированные p для одного семейства
из шести проверок. Для GT и Regionlet в семейство входят H1, разность
допустимых длин H2 и запас RFP. Недоступная проверка сохраняет своё место
в семействе со статусом `unavailable` и `p=1`.

## Фиксация и проверка итогового протокола

Создайте фиксацию после утверждения параметров и коммита протокола. Обе
команды требуют чистой рабочей копии. Манифест сохраняется в игнорируемом
Git каталоге `runs/` либо вне репозитория. Существующий файл защищён от
перезаписи.

```bash
protocol_args=(
  --seqmap /path/to/evaluate_tracking.seqmap.training
  --labels-dir /path/to/label_02
  --regionlet-dir /path/to/det_02
  --manifest runs/protocol-freeze.json
)
uv run --locked sort-gap-study freeze-protocol "${protocol_args[@]}"
uv run --locked sort-gap-study verify-protocol "${protocol_args[@]}"
```

В манифест входят Git-коммит, обе части split, версии Python и основных
библиотек, ревизии OC-SORT и TrackEval, SHA-256 конфигурации, файлов
зависимостей, seqmap и пар GT/Regionlet для каждого итогового видео.
Доступность закреплённых сторонних исходников проверяется в обеих командах.
Пути к локальным копиям можно передать через `--ocsort-checkout` и
`--trackeval`. При переносе данных сверяются контрольные суммы по роли и
номеру видео.

Перед итоговой оценкой выполните `verify-protocol` с теми же входами, которые
будет читать итоговый запуск. При ошибке команда завершится с ненулевым кодом.

Запуск итоговой сетки использует тот же манифест.

```bash
OPENBLAS_NUM_THREADS=1 uv run --locked sort-gap-study run-final \
  "${protocol_args[@]}" --output runs/final --workers 12
```

Команда проверяет фиксацию и работает с копией входов. Каждый завершённый
набор из двух входов и трёх методов сохраняется целиком. Для продолжения
после прерывания используйте тот же каталог, манифест и параметры команды.
Сводки, графики, интервалы и результаты поправки Holm появляются в
`results/` после завершения всей сетки.
