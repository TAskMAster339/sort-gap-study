# Материалы и методы

Статус — проект спецификации. Численные значения и ревизии в этом документе являются стартовыми параметрами пилота.

## Подготовка наблюдений

В GT-режиме выбираются записи `Car` с неотрицательным ID, конечными координатами и положительными шириной и высотой прямоугольника. На вход трекера поступают только `[x1, y1, x2, y2, 1]`. Идентификаторы, признаки окклюзии и усечения остаются в разметке для оценки.

В режиме Regionlet используются строки формата KITTI Tracking. Номер кадра берётся из поля 0, класс из поля 2, координаты из полей 6–9, уверенность из поля 17. Индексация полей начинается с нуля. Сохраняются записи `Car` с валидным прямоугольником и конечной уверенностью `score ≥ 0.0`. После фильтрации на вход всех трекеров поступает `[x1, y1, x2, y2, 1]`. Координаты и номера кадров сохраняются в исходной системе.

## SORT

Состояние фильтра Калмана — `(cx, cy, s, r, vx, vy, vs)`, где `s = w × h`, `r = w / h`. Измерение содержит `(cx, cy, s, r)`. Модель перехода прибавляет к центру и площади соответствующие скорости за один исходный кадр. Отношение сторон и скорости сохраняются при прогнозе. Скорости нового трека инициализируются нулями.

| Параметр | Значение для пилота |
| --- | --- |
| Начальная ковариация `P0` | `diag(10, 10, 10, 10, 10000, 10000, 10000)` |
| Ковариация шума процесса `Q` | `diag(1, 1, 1, 1, 0.01, 0.01, 0.0001)` |
| Ковариация шума измерения `R` | `diag(1, 1, 10, 10)` |

Если прогноз площади `s + vs` неположителен, перед прогнозом `vs` обнуляется. При обратном преобразовании нижняя граница площади и отношения сторон равна `1e-6`.

Основная ассоциация допускает пары с `IoU ≥ 0.3` и стоимостью `1 − IoU`. Назначение один к одному сначала максимизирует число допустимых пар, затем минимизирует их суммарную стоимость. Фиктивные назначения позволяют оставить трек или детекцию без пары. Недопустимые пары исключаются при решении задачи назначения.

## Дополнительная ассоциация

Дополнительный этап применяется только на первом доступном кадре после искусственной паузы. В него входят оставшиеся после основной ассоциации детекции и несопоставленные подтверждённые треки, которые остаются живыми и получили последнее реальное наблюдение непосредственно перед началом паузы. Такие треки считаются пережившими искусственный пропуск.

Для центра детекции вычисляются инновация `d = z_center − Hc × x_pred` и её ковариация `S = Hc × P_pred × Hcᵀ + R_center`. Матрица `Hc` выбирает две координаты центра. `R_center` — блок ковариации измерения для этих координат. Квадрат расстояния Махаланобиса `m = dᵀ × S⁻¹ × d` рассчитывается по прогнозу до коррекции.

Для допустимой пары одновременно выполняются условия:

- `m ≤ 9.21034`.
- `a = ||d|| / diag_length(bbox_pred) ≤ 2`.
- `b = max(w_det / w_pred, w_pred / w_det, h_det / h_pred, h_pred / h_det) ≤ 2`.

Стоимость допустимой пары равна `0.5 × m / 9.21034 + 0.3 × a / 2 + 0.2 × ln(b) / ln(2)`. Используется тот же порядок глобального назначения с возможностью оставить элементы без пары. После обоих этапов обновляются сопоставленные треки. Новые треки создаются из оставшихся детекций в порядке входных строк.

## Жизненный цикл и OC-SORT

Для пилота `max_age = 30` исходных кадров у всех трёх методов. До ассоциации трек удаляется, если разность текущего кадра и кадра последнего реального наблюдения превышает `max_age`. Подтверждение происходит после трёх реальных наблюдений суммарно, включая создание. Подтверждённые живые треки выдают оценку на каждом кадре, включая искусственные паузы и естественно пустые кадры. Для обоих вариантов SORT правила идентичны. Максимальная серия основной сетки составляет 10 кадров.

OC-SORT подключается через адаптер к `update` ревизии `8462e7e729a93ccd3bd995c0a79a890336cb3a0b`. Стартовые параметры — `delta_t = 3`, `inertia = 0.2`, `IoU = 0.3`, `BYTE = false`. Адаптер применяет общий срок хранения и подтверждение, вызывает обновление на каждом исходном кадре и выдаёт текущие оценки подтверждённых треков. Внутреннее восстановление виртуальной траектории корректирует состояние на текущем кадре. Записанные прогнозы предыдущих кадров сохраняются без изменений. [Исходный код OC-SORT](https://github.com/noahcao/OC_SORT/blob/8462e7e729a93ccd3bd995c0a79a890336cb3a0b/trackers/ocsort_tracker/ocsort.py)

## Оценка KITTI

Для оценки класса Car используется `Kitti2DBox` из TrackEval ревизии `12c8791b303e0a0b50f753af204249e622d0281a`. На участке оценки передаётся полная разметка со всеми классами и областями `DontCare`.

1. При предобработке выполняется сопоставление по IoU с порогом 0,5. Прогнозы, сопоставленные с `Van` или с GT при `occlusion > 2` либо `truncation > 0`, исключаются.
2. Для оставшихся несопоставленных прогнозов действуют исключения по высоте до 25 пикселей включительно и покрытию областью `DontCare` более чем на 50% площади прогноза.
3. Из оцениваемой GT исключаются `Van`, другие классы и экземпляры с указанными признаками окклюзии или усечения. Порог высоты применяется к несопоставленным прогнозам. Граничные сравнения определяются закреплённым кодом. [Предобработка Kitti2DBox](https://github.com/JonathonLuiten/TrackEval/blob/12c8791b303e0a0b50f753af204249e622d0281a/trackeval/datasets/kitti_2d_box.py)

Рассчитываются IDF1, HOTA, DetA, AssA, FP, FN, IDSW и Frag. Для RFP используется FP из CLEAR и число оцениваемых экземпляров Car после предобработки. Агрегирование и критерии решения описаны в [гипотезах](hypotheses.md).
